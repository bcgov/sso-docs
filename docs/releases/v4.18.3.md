# CSS v4.18.3
2026-11-16

### New Features 🎉
#### Organizations now available in the CSS App
Organizations introduce a new permission model across both the CSS App and CSS API, making it easier to manage integrations across multiple teams from a central location.
Key capabilities include:
- Group multiple teams under a single organization with shared members and CSS API service accounts.
- Allow each team to control exactly what the organization can access, down to individual integrations.
- Teams can revoke organization access at any time, maintaining full ownership and control of their integrations.
To request a new organization, please contact the SSO Team. For more information, see the [Organizations documentation](https://bcgov.github.io/sso-docs/css-application/organizations).

#### Enhanced Audit Logging
Audit capabilities have been significantly expanded. All major CSS App and CSS API events are now logged, providing improved visibility and traceability for administrative and integration activities.

For a complete list of audited events, see the [Audit events documentation](https://github.com/bcgov/sso-requests/blob/dev/docs/events.md). 
  

### Bug fixes and enhancement 🐛
- Removed role assignments from the UI when they no longer align with the selected identity providers (IDPs). Previously, if an integration had IDIR role assignments and IDIR was later removed as an IDP, the associated role assignments would still be displayed.
- Added a clear error message during CSS App sign-in for users who do not have an email address associated with their account. This helps ensure users maintain up-to-date contact information.
- Added pagination to the user role assignment page, improving performance and usability for integrations with large numbers of role assignments. 


### Miscellaneous 🧩
- Migrated logging from the SSO Loki platform to SIEM, reducing duplicate log storage and improving operational efficiency.
- Removed the client ID and privacy zone information from the BCSC payload token scope claim, as including these values caused issues for downstream services. This information remains available through the identity_provider and authentication_zone_identifier payload claims.
- Addressed technical debt and remediated vulnerabilities identified by GitHub Dependabot and other security scanning tools.
